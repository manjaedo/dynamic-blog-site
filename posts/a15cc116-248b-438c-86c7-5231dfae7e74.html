React 상태 관리, 어디에 둘까?

상태를 컴포넌트 가까이에 두는 이유와 서버 상태를 분리하는 기준을 정리했습니다.

React를 처음 배우면 모든 상태를 한곳에 모아야 할 것 같습니다. 하지만 작은 화면에서는 상태를 최대한 사용하는 곳 가까이에 두는 편이 훨씬 단순합니다.

1. 상태는 가까이에

검색어처럼 한 화면에서만 쓰는 값은 페이지 컴포넌트의 로컬 상태로 충분합니다. 전역 저장소에 넣는 순간, 필요 없는 곳까지 다시 렌더링될 가능성이 생깁니다.

Code 
const [query, setQuery] = useState('');
const [page, setPage] = useState(1);

2. 서버 상태는 따로

글 목록, 글 상세처럼 서버에서 오는 데이터는 로컬 UI 상태와 성격이 다릅니다. 로딩, 오류, 재요청, 페이지네이션을 함께 다뤄야 하므로 별도의 훅으로 분리하는 것이 좋습니다.

  • 로컬 상태: 입력값, 모달 열림, 탭 선택
  • 서버 상태: 글 목록, 글 상세, 태그 카운트

전역 상태는 마지막 수단으로 남겨 두면 구조가 훨씬 읽기 쉬워집니다.
